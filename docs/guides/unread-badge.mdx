---
title: Unread badge
description: Show users that a reply is waiting, on the button that opens Feddy or anywhere else in your app.
---

By the end of this page, the button that opens Feddy will show how many replies are waiting, and the number will disappear once the user has read them.

You don't have to keep the count up to date yourself. The SDK checks for new replies on its own: every 30 seconds on iOS, and every 45 seconds on the web plus whenever the user returns to the tab.

## iOS

### A row in a List or Form

```swift
Form {
    Button("Support") { Feddy.present() }
        .feddyUnreadBadge()
}
```

This is the same badge iOS puts on rows in the Settings app. Nothing is drawn when the count is zero.

### A row that draws its own chevron

A list badge sits at the trailing edge of the row, which would put it outside your chevron. Place the marker yourself instead:

```swift
HStack {
    Text("Support")
    Spacer()
    FeddyUnreadDot(showsCount: true)
    Image(systemName: "chevron.forward")
}
```

Pass `showsCount: false` for a plain dot without the number.

### A tab bar item or anything custom

Read the count from `FeddyUnread.shared`. It's an observable object, so a SwiftUI view that reads it updates itself whenever the count changes:

```swift
struct RootTabs: View {
    @ObservedObject private var unread = FeddyUnread.shared

    var body: some View {
        TabView {
            SupportView()
                .tabItem { Label("Support", systemImage: "bubble.left") }
                .badge(unread.count)
        }
    }
}
```

In a UIKit app, assign a function to `Feddy.onUnreadCountChanged` and set `tabBarItem.badgeValue` from it.

### Keep it fresh when the app comes back

While the app is in the background, the SDK stops checking. When the user returns, ask for a fresh count right away so the badge is right before the next scheduled check:

```swift
.onChange(of: scenePhase) { phase in
    if phase == .active { Feddy.refresh() }
}
```

## Web

If you're using the floating chat button, there's nothing to do: it shows the count itself.

If you've turned it off with `launcher: false`, give Feddy a function to call whenever the count changes, and update your own element from it:

```js
Feddy.init({ projectId: 'fd_XXXXXXXXXXXXXXXX', launcher: false })

const badge = document.querySelector('#help-badge')
Feddy.onUnreadCountChanged = (count) => {
  badge.hidden = count === 0
  badge.textContent = String(count)
}
```

## What counts as unread

A reply is unread until the user opens the conversation it belongs to. Opening the list of conversations isn't enough on its own. Replies in closed conversations never count.
