---
title: Create a project
description: Sign up, create a project for your app or site, and copy its project ID.
---

Everything in Feddy is organized around projects. A project is the home for one app or website: its conversations, the people who wrote in, its settings, and the inbox your team answers from. You need one before you install anything, and creating it takes about a minute.

<Steps>
<Step title="Sign up">

Create an account at [dash.feddy.app](https://dash.feddy.app/signup). The free plan doesn't expire and covers everything in these docs.
</Step>
<Step title="Create a project">

Name it after your app or site. One project per product is the usual setup.

If you have an iOS app and a website for the same product, they can share a project as long as the same people answer both. Prefer two projects when you want separate inboxes.
</Step>
<Step title="Copy the project ID">

Open **Settings → Install**. The project ID starts with `fd_` followed by 16 characters. It's the only thing you need from the dashboard to get set up, and every quickstart asks for it.

<Check>
You have a project and its ID. Pick your platform on the [introduction](/introduction) and follow its quickstart.
</Check>
</Step>
</Steps>

<Note>
**The project ID isn't a secret.** It's built into your app or visible in your page source, so anyone can find it, and that's fine: it only tells Feddy which inbox a message belongs to. Commit it, hard-code it, put it in a public repository. There's no way to rotate it and no need to. If someone tries to flood your inbox, Feddy limits how many requests one device can send.
</Note>

## One project for development and production

You don't need a separate project for testing. The SDK has an `apiUrl` option for pointing a development build at a local server, and the project ID stays the same either way. Create a second project only if you'd rather keep test conversations out of your real inbox.
